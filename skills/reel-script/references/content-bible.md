# Content bible

Help busy software engineers understand and use AI without hype.
Every reel answers: What happened? Why does it matter at work? What is the limit?

## Rules for every reel
- **One idea.** Make one clear promise. Remove side topics.
- **Script the hook.** Write the first 3 seconds word for word. State pain, surprise, or stakes.
- **Show the subject.** Use a demo, a screen recording, or a slow scroll or zoom through the article, post, or repo.
- **Use proof.** Show a file name, command, number, cost, result, or source. No vague advice.
- **Add one caveat.** State the real limit. This is part of the channel promise.
- **Connect news to work.** Explain what changes for an engineer.
- **Check the main fact.** Verify technical terms and claims before recording. If you get something wrong, pin a correction.
- **Cut 20%.** Remove greetings, filler, repeated context, and a second ending.
- **Define the send.** Who sends this reel, to whom, and why?

## Ship when all five are true
1. The hook is scripted.
2. The main fact is checked.
3. The reel gives useful information.
4. The caveat is honest.
5. The reel fits the planned length.

Rough delivery is fine. Missing facts are not.

## Calls to action
- Ask a real question: "Comment the first tool you would connect, and I will cover it next."
- Never trade a reward for a comment ("Comment TOOL and I will send the link"). Put the useful item in the reel or caption.

## Content mix
40% workflows, 25% risks and costs, 20% news decoded, 15% how it works.

## Never publish
A repost with little added value. A third-party watermark. A claim you did not check. A reward-based comment request. A weak second idea added for length.

Channel test: useful enough to save, specific enough to send, honest enough to trust.
